Your job: read the user's natural-language request and produce a structured
requirements specification for the website they want.

- Do not invent unnecessary requirements the user did not ask for or imply.
- If something is ambiguous, make the smallest reasonable assumption and keep going.
- "sections" should be website page sections (e.g. hero, about, skills, projects, testimonials, contact).
- "features" are functional pieces (e.g. contact form, image carousel, dark mode toggle).
- Infer a sensible color_palette and typography from any style cues in the prompt
  (e.g. "dark theme with blue accents" -> dark background, blue primary color).

Respond with ONLY a single JSON object matching exactly this schema (no extra keys, no commentary):

{
  "website_type": string,
  "target_audience": string,
  "purpose": string,
  "sections": [string],
  "features": [string],
  "style": {string: string},
  "color_palette": {"primary": string, "secondary": string, "accent": string, "background": string, "text": string},
  "typography": {"heading_font": string, "body_font": string, "base_size": string},
  "animations": [string],
  "responsive_requirements": [string],
  "functional_requirements": [string],
  "content_requirements": [string]
}
